## 五、全套术语速查表（遇到生词回这里查）

| 术语 | 英文 | 一句话解释 | 详见 |
|---|---|---|---|
| 大语言模型 | LLM | 读过海量文本、能接话的神经网络，本质是"预测下一个词元" | 01 |
| 词元 | Token | 模型处理文本的最小单位，计费/限长都按它算（中文约 1 字 ≈ 1 token） | 01/02 |
| 提示词 | Prompt | 发给模型的全部输入文字，工程里它是代码的一部分 | 02 |
| 上下文窗口 | Context Window | 一次请求能装下的最大 token 数（含历史+资料+问题） | 02 |
| 系统提示词 | System Prompt | messages 里 role="system" 的那条，定人设和规则 | 02 |
| 流式输出 | Streaming | 模型生成一点就推一点，前端打字机效果 | 01 |
| SSE | Server-Sent Events | HTTP 上"服务器单向连续推消息"的标准格式（`data: xxx\n\n`） | 01 |
| 函数调用 | Function Calling | 模型输出"我想调某工具+参数"的结构化 JSON，由你的代码真正执行 | 01 |
| 智能体 | Agent | LLM + 工具 + 循环：模型反复"决策→调工具→看结果"直到完成任务 | 01/05 |
| 嵌入向量 | Embedding | 把文字变成一串数字（如 2048 维），语义近则距离近 | 03 |
| 余弦相似度 | Cosine Similarity | 两个向量夹角的 cos 值，越接近 1 语义越像（检索打分标准） | 03 |
| 向量库 | Vector DB | 存向量并支持"找最近邻"的库：FAISS / pgvector / Milvus | 03 |
| 检索增强生成 | RAG | 先检索私有资料再让模型开卷回答，治幻觉+补私有知识 | 03 |
| 切块 | Chunking | 入库前把长文档切成 300-500 字带重叠的小段 | 03 |
| 混合检索 | Hybrid Search | 向量（语义）+ BM25（关键词）两路结果用 RRF 融合 | 03 |
| 重排 | Rerank | 粗排 top20 → 专门模型精排出 top3，精度更高 | 03 |
| 命中率 | hit@K | top-K 检索结果里含正确答案的问题占比，RAG 核心指标 | 03 |
| LangChain | — | Python LLM 应用工具箱：模型/模板/工具/记忆的统一封装 | 05 |
| LangGraph | — | 把 Agent 建模成"状态图"（节点=步骤，边=跳转，可循环） | 05 |
| MCP | Model Context Protocol | 工具接入的行业标准协议，写一次 Server 处处即插即用 | 05 |
| Spring AI | — | Spring 官方的 LLM 集成框架（Java 生态的 LangChain） | 06 |
| JVM | Java Virtual Machine | Java 程序运行的虚拟机：堆/栈/元空间 + GC | 06 |
| SseEmitter | — | Spring 里向浏览器推 SSE 流的对象 | 06 |

## 八、AI 使用规矩（本清单学习期间强制执行）

> 背景：blog 项目主要由 AI 按"代码编写指南"生成，代码好看但"会写"没被验证。
> 面试时手写代码没有 AI，项目被追问一层就必须自己扛。以下规矩用来把"AI 会"变成"我会"。

1. **顺序铁律：先自己写，再问 AI**
   - 动手前：可以让 AI 讲概念、讲思路（"FAISS 的 IndexFlatL2 是什么原理"）
   - 写代码：**必须自己从空文件敲**，卡住超过 30 分钟才可以让 AI **给提示**（不是给完整代码）
   - 写完后：可以让 AI review 你的代码、指出问题，然后**自己改**
2. **禁用**：让 AI 整段/整文件生成核心逻辑 → 复制粘贴。样板代码（依赖配置、测试脚手架）除外
3. **重写自检**：每个模块通关后，关掉笔记和 AI，把核心代码（如 01 的 FC 循环、03 的建索引脚本）从空文件重写一遍；重写不出来 = 还不属于你，回炉
4. **讲得出才算会**：每个模块做完，能不看代码向别人讲清"这段为什么这么写"（比如为什么用 LEFT JOIN 而不是 INNER JOIN）
5. **AI 心得继续记**：这些规矩本身（什么时候忍不住想抄、怎么防）就是 04 号笔记的使用心得素材
